# W4 — `vfio_user_device` client MSI-X SET_IRQS eventfd

> **执行方式：inline（控制者本人执行，非 subagent-driven）。** 单 commit。
>
> **Plan type: 新功能（TDD）。** client SET_IRQS eventfd 是真新代码。loopback 对接真 `VfioUserSession` + `IrqTriggerDev`（doorbell→ctx.fire_interrupt 写 eventfd）证中断送达，对标 POC-2。
>
> **⚠️ 单 commit 纪律（用户 2026-06-11）**：整个 W4 合成**一个 commit**。见 [[commit-granularity-coarse-not-per-step]]。
>
> **重大利好（explore D2/D3 核实）**：client 建/读/dup eventfd 是**全 safe nix API**（`EventFd::from_value_and_flags` → `OwnedFd`，`nix::unistd::{read,write,dup}` 全 safe；无 `from_raw_fd`）。**W4 保持 `#![deny(unsafe_code)]` 不变**。多 fd SCM_RIGHTS：W3 的 `write_message_with_fds(&[RawFd])` 已支持多 fd，**framing 无需改**。
>
> **scope ADR（explore C，选项 A）**：W4 = **client SET_IRQS eventfd + loopback fire 观测**（eventfd 计数++ = 中断送达 client 半段）。**`Interrupt::deliver`（VTL0 guest 注入）推迟 W6**——需 openvmm/underhill partition + `vmcore::interrupt`，无法 standalone 测（与 W2 PCIe 呈现 / W3 JIT 同构）。spec §6 W4 落地后记此 ADR。
> **语义双关注意**：`vfio_user_transport/docs/specs/2026-06-05-*.md` 表里的 "W4 = Backend::inject_msix" 是 **server/QEMU-backend 视角**，与本 client-side W4（配 eventfd）**不是同一 W4**——commit/plan 点明避免混淆。

**Goal:** client 能配下 MSI-X 触发 eventfd（`set_irqs(index, start, eventfds)`，多 fd 经 SCM_RIGHTS），server 收下存 `IrqVectors`；device fire 中断时写该 eventfd，loopback 验 client 持有的 eventfd 计数++（中断 firmware→client 半段送达）+ 其它向量不误触发（POC-2 两断言）。

**Architecture:** 复用 W3 `framing::write_message_with_fds`（已支持多 fd）+ W2 `expect_reply`。`VfioUserClient` 加 `set_irqs`（assign）+ 可选 `set_irqs_deassign`/`set_irqs_clear`（对齐 server 三态）。eventfd 建/读全 safe nix（需 nix `event` feature）。loopback 新 `IrqTriggerDev`（doorbell→`ctx.fire_interrupt`）。production deps 仅 nix 加 `event` feature。

**Tech Stack:** Rust 2024，rustc 1.95；nix 加 `event` feature；**保持 `#![deny(unsafe_code)]`**。

### Step 2.2: set_irqs（assign）+ deassign + clear

```rust
    // ── W4: MSI-X SET_IRQS eventfd ──

    /// SET_IRQS assign：把 `eventfds` 配给 MSI-X 向量 `[start, start+len)`，server
    /// 后续 fire 该向量时写对应 eventfd（8 字节 u64+=1）。多 fd 经 SCM_RIGHTS。
    ///
    /// `index` 通常 `pci_irq::MSIX`。reply 是 header-only OK。
    pub fn set_irqs(
        &mut self,
        index: u32,
        start: u32,
        eventfds: &[BorrowedFd<'_>],
    ) -> anyhow::Result<()> {
        let raw: Vec<RawFd> = eventfds.iter().map(|fd| fd.as_raw_fd()).collect();
        let req = IrqSetPayload {
            argsz: core::mem::size_of::<IrqSetPayload>() as u32,
            flags: irq_set::DATA_EVENTFD | irq_set::ACTION_TRIGGER,
            index,
            start,
            count: eventfds.len() as u32,
        };
        self.send_set_irqs(&req, &raw)
    }

    /// SET_IRQS deassign：清 MSI-X 向量 `[start, start+count)` 的 eventfd（发 0 fd，
    /// = vfio-user 全 `-1` 编码 / 掩码）。
    pub fn set_irqs_deassign(&mut self, index: u32, start: u32, count: u32) -> anyhow::Result<()> {
        let req = IrqSetPayload {
            argsz: core::mem::size_of::<IrqSetPayload>() as u32,
            flags: irq_set::DATA_EVENTFD | irq_set::ACTION_TRIGGER,
            index,
            start,
            count,
        };
        self.send_set_irqs(&req, &[])
    }

    /// SET_IRQS clear：DATA_NONE + count=0，清整个 IRQ 向量数组。
    pub fn set_irqs_clear(&mut self, index: u32) -> anyhow::Result<()> {
        let req = IrqSetPayload {
            argsz: core::mem::size_of::<IrqSetPayload>() as u32,
            flags: irq_set::DATA_NONE | irq_set::ACTION_TRIGGER,
            index,
            start: 0,
            count: 0,
        };
        self.send_set_irqs(&req, &[])
    }

    /// SET_IRQS 公共发送：payload = IrqSetPayload（无 trailing data），fd 经 SCM_RIGHTS。
    fn send_set_irqs(&mut self, req: &IrqSetPayload, fds: &[RawFd]) -> anyhow::Result<()> {
        let msg_id = self.alloc_msg_id();
        let hdr = Header::command(
            msg_id,
            Command::DeviceSetIrqs,
            core::mem::size_of::<IrqSetPayload>() as u32,
        );
        write_message_with_fds(&mut self.stream, &hdr, req.as_bytes(), fds)
            .context("send SET_IRQS")?;
        let reply = read_message(&mut self.stream).context("recv SET_IRQS reply")?;
        Self::expect_reply(&reply, msg_id, Command::DeviceSetIrqs)?;
        Ok(())
    }
```

注意：
- `Command::DeviceSetIrqs` 变体名 + 值（grep proto.rs Command enum 确认；explore 提 SET_IRQS=8）。
- `IrqSetPayload` 字段 `argsz/flags/index/start/count`（proto.rs:313 确认，20B）。
- `irq_set::{DATA_EVENTFD, DATA_NONE, ACTION_TRIGGER}`（proto.rs:395 确认）。

## Stage 3 — loopback MSI-X fire 集成测

**Files:** `vfio_user_device/tests/loopback_msix.rs`

设计（选项 A，对标 POC-2）：
- client 建 N=4 个 `EventFd`（safe nix）。
- `IrqTriggerDev`（doorbell offset → `ctx.fire_interrupt(VEC)`）。
- client `set_irqs(MSIX, 0, &eventfds)` 配下 → `region_write(doorbell)` 驱 device fire → server 写 client 的 eventfd（同一内核对象）→ client read eventfd 验计数++ + 其它向量未误触发。
- **时序利好**：`fire_interrupt` 在 `mmio_write` 内（handle_region_write 发 reply **之前**同步执行），故 client 收 region_write reply 时 eventfd 已 signaled，blocking read 立即返回。

```rust
// Copyright (c) Microsoft Corporation.
// Licensed under the MIT License.

//! W4 loopback 集成测：client SET_IRQS 配 MSI-X eventfd → server device
//! fire_interrupt 写 eventfd → client read 验计数++（中断 firmware→client 半段
//! 送达）。对标 POC-2。socketpair + eventfd，Linux 直跑，无需 VTL。
//!
//! 注：`Interrupt::deliver`（注入 VTL0 guest）推迟 W6（需 underhill partition，
//! 非 standalone）。本测只验"中断写到 client eventfd"半段。

use nix::sys::eventfd::EfdFlags;
use nix::sys::eventfd::EventFd;
use pcie_device_core::BarKind;
use pcie_device_core::BarLayout;
use pcie_device_core::DeviceCtx;
use pcie_device_core::DeviceDescribe;
use pcie_device_core::PcieDevice;
use std::os::fd::AsFd;
use std::os::unix::net::UnixStream;
use std::thread;
use vfio_user_device::VfioUserClient;
use vfio_user_wire::proto::pci_irq;

const DOORBELL: u64 = 0x1000;
const FIRE_VEC: u32 = 1; // device fire 的向量号

/// doorbell @ DOORBELL → ctx.fire_interrupt(FIRE_VEC)。
struct IrqTriggerDev;
impl PcieDevice for IrqTriggerDev {
    fn describe(&self) -> DeviceDescribe {
        DeviceDescribe {
            vendor_id: 0x1234,
            device_id: 0x5678,
            class_code: 0x01_08_02,
            revision: 1,
            subsystem_vendor: 0,
            subsystem_device: 0,
            bars: vec![BarLayout {
                index: 0,
                size: 8192,
                kind: BarKind::Mmio32,
                prefetchable: false,
            }],
            msix_count: 4,
            capabilities: vec![],
            cfg_write_side_effect_offsets: vec![],
        }
    }
    fn mmio_read(&mut self, _bar: u32, _offset: u64, _size: u32) -> u64 {
        0
    }
    fn mmio_write(
        &mut self,
        ctx: &mut DeviceCtx<'_>,
        _bar: u32,
        offset: u64,
        _size: u32,
        _value: u64,
    ) {
        if offset == DOORBELL {
            ctx.fire_interrupt(FIRE_VEC);
        }
    }
}

fn spawn_server(server_end: UnixStream) -> thread::JoinHandle<anyhow::Result<()>> {
    thread::spawn(move || -> anyhow::Result<()> {
        let mut s = server_end;
        let neg = vfio_user_transport::server_handshake(&mut s)?;
        let mut sess = vfio_user_transport::VfioUserSession::new(s, neg);
        let mut dev = IrqTriggerDev;
        while sess.pump_one(&mut dev)? {}
        Ok(())
    })
}

#[test]
fn loopback_msix_fire_signals_eventfd() {
    // client 建 4 个 eventfd（counter 起始 0）。
    let efds: Vec<EventFd> = (0..4)
        .map(|_| EventFd::from_value_and_flags(0, EfdFlags::empty()).unwrap())
        .collect();
    let borrowed: Vec<_> = efds.iter().map(|e| e.as_fd()).collect();

    let (server_end, client_end) = UnixStream::pair().unwrap();
    let server = spawn_server(server_end);

    let mut client = VfioUserClient::from_stream(client_end);
    client.handshake().expect("handshake");

    // 1. SET_IRQS 配下 4 个 eventfd 给 MSI-X 向量 [0,4)。
    client
        .set_irqs(pci_irq::MSIX, 0, &borrowed)
        .expect("set_irqs assign");

    // 2. doorbell：BAR0 REGION_WRITE @ DOORBELL → server device ctx.fire_interrupt(FIRE_VEC)
    //    → server 写 client eventfd[FIRE_VEC]。fire 在 mmio_write 内（reply 前同步），
    //    故收到 region_write reply 时 eventfd 已 signaled。
    client
        .region_write(0, DOORBELL, &1u32.to_le_bytes())
        .expect("doorbell region_write");

    // 3. 验 fire 的向量 eventfd 计数 == 1（中断送达）。
    let mut buf = [0u8; 8];
    nix::unistd::read(&efds[FIRE_VEC as usize], &mut buf).expect("read fired eventfd");
    assert_eq!(u64::from_ne_bytes(buf), 1, "fire 的向量 eventfd 计数应 ==1");

    // 4. 其它向量未被误触发：用 nonblock dup 读，应 EAGAIN（无数据）。
    //    （EventFd 默认 blocking，直接 read 会挂；故对未 fire 的向量做 nonblock 探测。）
    for (i, e) in efds.iter().enumerate() {
        if i == FIRE_VEC as usize {
            continue;
        }
        let probe = nix::unistd::dup(e.as_fd()).expect("dup probe");
        // 设 nonblock 后 read：未 fire → EAGAIN。
        use nix::fcntl::{fcntl, FcntlArg, OFlag};
        let cur = fcntl(probe.as_fd(), FcntlArg::F_GETFL).unwrap();
        fcntl(
            probe.as_fd(),
            FcntlArg::F_SETFL(OFlag::from_bits_truncate(cur) | OFlag::O_NONBLOCK),
        )
        .unwrap();
        let mut b = [0u8; 8];
        let r = nix::unistd::read(&probe, &mut b);
        assert!(
            matches!(r, Err(nix::errno::Errno::EAGAIN)),
            "向量 {i} 不应被触发（应 EAGAIN），got {r:?}"
        );
    }

    drop(client);
    server.join().unwrap().expect("server loop");
}
```

注意：
- `EventFd::from_value_and_flags(0, EfdFlags::empty())` / `as_fd()` / `nix::unistd::{read,dup}` —— 全 safe（server irq.rs:272-322 同款），test 无 unsafe。
- `nix::fcntl` 设 O_NONBLOCK：需 nix `fs` feature？或 `fcntl` 在默认/socket？**执行时确认 `nix::fcntl::fcntl` 所需 feature**——若需额外 feature，改用 `EventFd::from_value_and_flags(0, EfdFlags::EFD_NONBLOCK)` 对未 fire 向量另建探测（但那是另一对象，counter 不共享）。**更简方案**：未 fire 向量的"不误触发"验证改为——只验 fire 向量 ==1 即可（POC-2 的核心断言是 fire 向量送达；"其它不误触发"是加分项）。若 fcntl feature 麻烦，**删掉 step 4 的 nonblock 探测**，保留 step 3 核心断言。
- `pci_irq::MSIX`（proto.rs:379，值 2）。
- 时序：fire 在 mmio_write（reply 前），blocking read step 3 立即返回。
